# 缝隙笔记：违和感的收集、识别与升级

> 核心：开一个固定收集位，**只记一类东西："这里不对劲"**。缝隙不是聪明看出来的，是时间泡出来的——对某件事熟到看见"这里本该如此、却不是如此"的违和感时，突破性想法才会出现。这就是壁垒的来源。**记的是异常，不是待办。**

## 一、三类违和感的识别例

### 1. 流程里说不通的环节

```
识别信号："为什么这一步要这样？"——答不上来，或答出来的理由经不起追问
例：
  - 数据要人工从 A 系统抄到 B 系统（"因为接口没通"——但为什么三年没通？）
  - 审批要 5 个人签字（"因为规定"——规定为什么这么定？砍到 2 个行不行？）
  - 发布前必须手动点 3 个检查（"因为历史上出过事"——那次的事现在还会发生吗？）
判据：说不通 = 缝隙；"历来如此" = 最高价值的缝隙（默认≠合理）
```

### 2. 用户反复抱怨却没人改的点

```
识别信号：同一个抱怨出现 ≥3 次（不同的人、不同的场合，抱怨同一个点）
例：
  - "每次导出都是乱码"（3 个用户在不同周提到）
  - "搜索找不到 XX"（用户群 + 工单 + 访谈都提到）
  - "这个功能要换三个页面才能用完"（反复被吐槽，但需求池里排不上）
判据：≥3 次才记（一次是噪音，三次是信号）；
  抱怨的"没人改"才是缝隙的关键——有人改=已处理；没人改=缝隙（且通常有原因：
  改不动/没权限/看不见/不值得——找到那个原因=缝隙的深度）
```

### 3. 行业里大家默认但其实没道理的做法

```
识别信号："都说要这样"——但查不到"为什么"（或查到的理由站不住）
例：
  - "行业里都要做 XX 认证"——为什么？不做会怎样？（查不到的"为什么"=缝隙）
  - "这个环节必须用 XX 工具"——为什么不能用别的？（默认的工具依赖=缝隙）
  - "客户都这样要求"——客户为什么这样要求？（客户的默认往往来自他上游的默认）
判据：默认做法的"为什么"查不到 or 理由失效（条件变了做法没变）= 缝隙
```

## 二、<2 分钟记录格式（重了就会死）

```markdown
<日期> | <场景一句话> | 不对劲：<违和点一句话> | （可选）可能的解法方向
```

**示例**：
```
2026-10-02 | 周会过排期 | 不对劲：排期永远排满，缓冲被吃完就延期，但没有人为"总是延期"负责 | 解法方向：谁排的满谁承担延期成本？
2026-09-28 | 用户访谈 | 不对劲：三个用户都说"找不到入口"，但入口就在那 | 解法方向：不是入口问题，是心智模型问题（用户以为在别处）
2026-09-15 | 读行业报告 | 不对劲：所有报告都用同一个指标，但没人解释为什么是这个指标 | 解法方向：这个指标可能是"好统计"不是"有意义"
```

**纪律**：
```
[ ] 每条 <2 分钟（写不完=砍，缝隙笔记死于太重）
[ ] 只记异常不记待办（写成"待办"→ 被排期吃掉 → 下次还是异常 → 循环但从不升级）
  判别：写完这条，它是"要去做的事"还是"值得琢磨的现象"？后者才进缝隙笔记
[ ] 不要求解法（当时想不到就不写；解法是升级阶段的事，不是记录阶段的事）
```

## 三、噪音 vs 真缝隙（≥3 次规则 + 深度检验）

```
噪音特征（不升级）：
  - 单次出现（可能是个案/个例/表达误差）
  - 每次表述都不一样（没有共同的"点"，只是都"不顺"）
  - 抱怨的人/场景都在变（没有稳定的对象）
真缝隙特征（可升级）：
  - 同类违和感出现 ≥3 次（同一"点"，不同时间/不同来源）
  - 能一句话说出"本该如此、却不是如此"（说不出=还没看穿，继续记）
  - 能问出"为什么没人改"（答案指向结构原因：没权限/看不见/改不动/利益相关）
深度检验（升级前必做）：
  "为什么这事没人改？"
    答得出（如：改了要动 X 部门的利益）→ 缝隙深（结构性，价值高）
    答不出 → 缝隙浅（可能是没人想到，价值低，先放着）
```

## 四、三种出口（缝隙升级路径）

```
出口 1：慢仓项目（最深的缝隙）
  条件：≥3 次 + 深度检验过（结构性原因）+ 反向三问过
  动作：立项（具体名字/季度证据标准/每周小时数/退出判据，见 slow-fast-ledger）
  价值：这是"壁垒"的直产出——别人看不见的缝隙，你看见了且改掉了
出口 2：选题/内容/方法论（可表达的缝隙）
  条件：≥3 次 + 能一句话说清（"本该如此却不是如此"说得清）
  动作：写成拆解/文章/分享（写作的过程=第二次检验——说不清=还没看穿，打回继续记）
  价值：可复用资产（写出来的东西还在替你说）
出口 3：升职叙事素材（缝隙的"证据化"）
  条件：你已经在改它（哪怕小步）+ 有前后对比
  动作：记录"我看见了什么（缝隙）→ 我做了什么（动作）→ 改变了什么（结果）"
  价值：绩效/晋升/转岗时，"我改了一个没人改的结构性问题"
  比"我完成了 KPI"值钱一个量级（前者证明你看得见别人看不见的，后者只证明你听话）
```

**升级的纪律**：每周复盘翻一遍缝隙笔记时，只做一件事——数"同类出现≥3 次"的条目。有 → 评估走哪个出口。没有 → 不做任何动作（缝隙升级是低频事件，每周强求一个出口=制造伪缝隙）。

## 五、笔记腐化的信号与维护

```
腐化信号（出现任一 = 笔记已死或快死）：
  S1 三周没新增（违和感还在但你懒得记 → 收集位失效，换更轻的入口：
     手机备忘录/语音转文字，先把"记"的动作成本降到 30 秒以下）
  S2 记录变长（>2 分钟/条 → 你在分析而不是记录；砍回一句话，分析留到复盘）
  S3 开始记待办（"这里不对劲"变成了"要去修这里" → 异常混进了任务，
     笔记变成第二待办清单，永远不被当原料翻 → 物理分开：任务进排期，异常留笔记）
  S4 复盘不翻（连续两周复盘没翻缝隙笔记 → 它不在工作流里 = 不存在；
     把"翻缝隙笔记"写进周复盘模板的固定项，和风向筛同级）
维护节奏：
  日常：随手记（<2 分钟/条）
  每周：复盘时翻一遍，数 ≥3 次的同类（5 分钟）
  每月：看一次"出口"——这个月有没有缝隙该升级了？（和月度乐趣校准合并做）
```
