# 快慢双仓：慢仓怎么立、怎么保、怎么查

> 核心：快仓保今天能活（交付/响应/日常指标），慢仓保三年后在上风口（难、短期没回报、方向明确）。**慢仓不看周报、不设短 KPI，只按季度检查一次"是否还在往前挪"。它被牺牲掉的那天，就是你开始滑向下风口的那天。**

## 一、慢仓立项标准（什么值得进慢仓）

```
进慢仓 = 三问过 + 上风口 + 难而正确（三者交集，缺一不可）
  三问过：难 + 三年成立 + 带出下一步（见 reverse-questions.md）
  上风口：做完复利累积（资产/能力/关系，见 wind-screening.md）
  难而正确：既有热情（乐趣校准能过），又难得住人（Q1 参照系检验）
立项四要素（缺一个 = 慢仓立不住）：
  1. 具体名字（不是"学底层能力"，是"吃透 X 系统核心链路并写出拆解"）
  2. 季度推进证据标准（本季度结束时能拿出什么，见下"证据标准"）
  3. 每周固定小时数（从 30% 上风口时间里切出来，锁日历）
  4. 退出判据（什么情况下放弃/换方向，提前写，防沉没成本绑架）
```

**慢仓容量**：同时慢仓项目 ≤2 个。3 个以上 = 每个都是"长期项目"，每个都不会推进（注意力是慢仓最稀缺的资源，比时间还稀缺——时间是 40 小时/周，注意力只有 2-3 个焦点）。

## 二、"往前挪"的证据标准（防自我欺骗的核心）

```
季度检查只问一个问题：是否还在往前挪？
"挪动"必须可指认，三种证据（至少满足一种）：
  E1 新看懂了：这个季度能具体说出"上季度看不懂、现在看得懂"的东西
     （具体到章节/模块/机制——"感觉更懂"不算）
  E2 新解释力：比上季度能多解释一层什么
     （检验：让一个同行问一个问题，你能答出上季度答不出的深度）
  E3 新产物：产出了不可见的东西
     （拆解文档/原型/能回答的新问题清单/别人能用的拆解）
不算证据的（自我欺骗高发区）：
  ✗ "在积累"（积累是什么？指不出来 = 没有）
  ✗ "还没到出活的时候"（每个季度都是"还没到" = 永远不出活）
  ✗ "读了 X 本书/文档"（输入量≠挪动；检验：读完能回答什么以前答不出的？）
  ✗ "在等时机"（等=没挪；时机是做成后的事，不是没挪的借口）
```

## 三、季度检查 30 分钟流程

```markdown
# 慢仓季度检查 <季度>
## 1. 挪动证据（对每个慢仓项目）
项目：<名字>
本季度证据（E1/E2/E3 至少一种）：
  - <具体指认>
判定：挪动/未挪动
## 2. 挤占审计（回看季度内）
慢仓被挤占次数：__（每次原因：<什么挤的>）
挤占模式：<见下"四种模式">
## 3. 缝隙输入
缝隙笔记里出现≥3 次的违和感：<有/无>
是否升级为慢仓候选：<是（列候选）/否>
## 4. 三问重过（世界在变，当时的"三年成立"要重验）
Q2 三年还成立吗？：<重验结论>
Q3 下一步还是那些吗？：<重验结论>
## 5. 结论（三选一）
  继续（证据达标 + 三问仍过）
  调项目（方向对但项目不对：换具体名字/换证据标准）
  换方向（三问挂了 or 连续两季度未挪动 → 回①重看风向）
```

**"连续两季度未挪动"的处置**：这不是努力问题，是方向问题——慢仓项目连续两季度拿不出 E1/E2/E3 证据，说明它不是"难"，是"不成立"（难的东西每季都有挪动，哪怕小；不成立的东西每季都在原地）。回①重看风向，别恋战。

## 四、慢仓被挤占的四种模式与应对

| 模式 | 症状 | 根因 | 应对 |
|---|---|---|---|
| **会议蚕食** | 慢仓时段被临时会占满 | 时段没锁死/没防御 | 锁日历+防御（见 wind-screening 第二节）；被占后当周不补，下周"还债" |
| **快仓膨胀** | 快仓任务越排越多，周末/晚间开始吃慢仓时间 | 快仓没设上限（来者不拒） | 快仓设容量上限（每周最多 N 个交付任务）；超上限=砍/降级/拒绝（用反向三问砍） |
| **紧急插队** | "今天必须"的活把慢仓全吃掉 | 无缓冲（排期排满=无弹性） | 每周留 10-15% 缓冲时间（不属于快仓也不属于慢仓，专门吃紧急）；缓冲被吃完=本周不再排新快仓 |
| **注意力漂移** | 时间还在用，但心思不在慢仓上（人在心不在，做快了） | 乐趣枯竭（月度校准为否但没动） | 月度乐趣校准（SKILL 第 0 步）；连续两月否=方向错，回① |

**关键区分**：前三种是结构问题（排期能修），第四种是方向问题（只有回①能修）。用排期手段修方向问题 = 永远修不好。

## 五、快仓如何不侵蚀慢仓（排期结构）

```
一周排期结构（从上到下，优先级倒序——下面的不能被上面的挤占）：
  [锁死] 慢仓/上风口：__h（30% 地板，精力最好时段）
  [弹性] 快仓交付：__h（设容量上限，超=砍/降级/拒）
  [缓冲] 紧急插队专用：__h（10-15%，吃完即止）
  [日常] 响应/会议/杂活：剩余
结构纪律：
  - 慢仓时段在日历上写"慢仓"占位符（不写任务名，挤占代价心理可见）
  - 快仓容量上限写死（本周最多接 N 个，不是"看情况"）
  - 缓冲是快仓的"保险丝"：保险丝烧了（缓冲吃完），本周快仓停接新的
被侵蚀的信号（周复盘时查）：
  慢仓实际 < 计划 × 80%（连续两周）→ 结构问题，查四种模式
  快仓实际 > 容量上限 × 120%（连续两周）→ 快仓超载，砍活
```

## 六、慢仓与快仓的转化（不是永远分开）

```
慢仓项目"做成了"之后：
  - 它可能变成快仓的资产（系统跑起来了，日常维护进快仓——但维护是消耗，
    改进/扩展仍是上风口，继续按上风口排）
  - 它可能带出新的慢仓项目（Q3 的"下一步"落地——这就是复利：
    慢仓做成 → 下一步自动出现 → 新慢仓立项）
  - 它可能变成对外资产（可复用资产类：方法论/产品/作品，开始被使用）
转化的标志：慢仓项目从"我在做"变成"它在替我工作/在替我带路"
  达到这个标志 = 慢仓成功（不是"做完了"，是"开始复利了"）
```
